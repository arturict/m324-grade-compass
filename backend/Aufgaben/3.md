### 3.1.2 Target `linting` im Makefile

> Automatisiere die Analyse mit einem Target `linting` im `Makefile`. Der Token darf nicht im `Makefile` stehen.

**Lösung:** siehe [Makefile](../../Makefile)

```makefile
-include .env

SONAR_HOST_URL ?= http://sonarqube:9000
SONAR_NETWORK ?= sonar-net
SONAR_TOKEN ?=

.PHONY: test clean coverage linting

coverage:
	mvn -f backend/pom.xml test
	mvn -f backend/pom.xml dependency:copy-dependencies -DoutputDirectory=target/dependency

linting: coverage
	docker run --rm \
		-e SONAR_HOST_URL="$(SONAR_HOST_URL)" \
		-e SONAR_TOKEN="$(SONAR_TOKEN)" \
		--network $(SONAR_NETWORK) \
		-v .:/usr/src \
		-u $$(id -u):$$(id -g) \
		sonarsource/sonar-scanner-cli
```

Der Token steht nicht im `Makefile`: Er wird aus `.env` gelesen (`-include .env`, Datei ist in `.gitignore`) oder beim Aufruf übergeben (`make linting SONAR_TOKEN=...`). `linting` hängt von `coverage` ab, damit vor jeder Analyse Tests, JaCoCo-Report und Libraries aktuell sind. `$$` ist nötig, damit `make` den Ausdruck `$(id -u)` an die Shell weitergibt.

## 3.3 Tests oder Code Analyse?

### 3.3.1 Beispiele

> Nenne je ein Beispiel für einen Fehler, den nur ein Test findet, und einen, den nur SonarQube findet.

**Nur ein Test findet:** falsche Logik, die sauber geschrieben ist. Beispiel aus 4.3.1: Grenze 50 statt 100 Zeichen, oder `update` liefert 404 statt 409. SonarQube kennt die Anforderung nicht.

**Nur SonarQube findet:** Probleme ohne sichtbares Fehlverhalten: ungenutzte Variablen und Imports, `System.out` statt Logger, auskommentierter Code, Namenskonventionen, hartcodiertes Passwort (3.4).

### 3.3.2 Weshalb ergänzen sie sich?

> Weshalb ergänzen sich die beiden Werkzeuge?

**Antwort:** Tests prüfen das **Verhalten**: Tut der Code das Richtige? Dafür wird er ausgeführt (dynamisch). SonarQube prüft die **Struktur**: Ist der Code verständlich, wartbar und sicher geschrieben? Dafür wird er nur gelesen (statisch). Zusätzlich zeigt SonarQube die Coverage aus JaCoCo und damit, wo Tests fehlen. Der leere `catch` wurde von beiden gefunden, aus verschiedenen Gründen.

Status: ✅ erledigt
