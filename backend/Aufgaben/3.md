### 3.1.2 Target `linting` im Makefile

> Automatisiere die Analyse mit einem Target `linting` im `Makefile`. Der Token darf nicht im `Makefile` stehen.

**Lösung:** siehe [Makefile](../../Makefile)

```makefile
-include .env

SONAR_HOST_URL ?= http://sonarqube:9000
SONAR_NETWORK ?= sonar-net
SONAR_TOKEN ?=

.PHONY: test clean coverage linting

coverage:
	mvn -f backend/pom.xml test
	mvn -f backend/pom.xml dependency:copy-dependencies -DoutputDirectory=target/dependency

linting: coverage
	docker run --rm \
		-e SONAR_HOST_URL="$(SONAR_HOST_URL)" \
		-e SONAR_TOKEN="$(SONAR_TOKEN)" \
		--network $(SONAR_NETWORK) \
		-v .:/usr/src \
		-u $$(id -u):$$(id -g) \
		sonarsource/sonar-scanner-cli
```

Der Token steht nicht im `Makefile`: Er wird aus `.env` gelesen (`-include .env`, Datei ist in `.gitignore`) oder beim Aufruf übergeben (`make linting SONAR_TOKEN=...`). `linting` hängt von `coverage` ab, damit vor jeder Analyse Tests, JaCoCo-Report und Libraries aktuell sind. `$$` ist nötig, damit `make` den Ausdruck `$(id -u)` an die Shell weitergibt.
